# Building and Publishing

## Setup

Use Node.js 22 LTS or newer. Run commands from the repository root:

```sh
npm ci
```

The root dependencies are sufficient for the full build; a separate install in
the blog directory is not required.

## Add a Blog Post

1. Copy [blog/template_single.html](blog/template_single.html) or
   [blog/template_series.html](blog/template_series.html) into the new post folder.
2. Write the article and replace the template placeholders, including its canonical
   URL. Use the public HTTPS URL with a trailing slash.
3. Add one entry to [blog/data/posts.json](blog/data/posts.json), keeping posts in
   chronological order. Paths are relative to the blog directory, without leading
   or trailing slashes:

   ```json
   {
     "title": "My New Post",
     "category": "Quality",
     "date": "2026-10-17",
     "path": "2026/MyNewPost",
     "excerpt": "A short plain-text summary of the post."
   }
   ```

4. Build the site:

   ```sh
   npm run build
   ```

5. Review and commit the article, metadata, generated files, and any changed
   bundles, then push using the usual publishing workflow.

The existing optional fields such as `parentKey`, `part`, `codeUrl`, and
`downloadUrl` continue to work. `rssGuid` is an optional permanent RSS identifier
for a post whose historical identifier differs from its path. Do not change an
existing identifier: feed readers may otherwise display that post as a new entry.
Normal new posts do not need this field.

## What the Build Does

`npm run build` first runs the metadata generator, then builds both JavaScript
bundles. [blog/data/posts.json](blog/data/posts.json) is the source for:

- [blog/data/rss.xml](blog/data/rss.xml): feed items, excerpts, categories, and dates.
- [blog/index.html](blog/index.html): only the marked fallback post-links block.
  The rest of this page remains manually editable.
- [sitemap.xml](sitemap.xml): the homepage, blog index, and all listed posts.
  Templates, the navigation-only table of contents, and category filters are excluded.

Generated sections include comments warning against manual edits. The generator
checks required metadata, valid dates, duplicate paths, and missing post pages
before writing. XML and HTML text are escaped. Existing RSS identifiers remain
stable, while RSS links and sitemap URLs use trailing slashes.

Feed dates come from publication dates, not the build clock. Running generation
again without changing metadata produces the same output.

The bundles are generated by webpack:

- [src/blog.js](src/blog.js) becomes [build/blog.bundle.js](build/blog.bundle.js).
- [blog/src/blog.js](blog/src/blog.js) becomes
  [blog/build/blog.bundle.js](blog/build/blog.bundle.js).

Do not edit bundle files directly. The root webpack configuration builds the
homepage; the blog webpack configuration builds the post and archive scripts.

## Commands

| Command, from repository root | Purpose |
| --- | --- |
| `npm run build` | Generate metadata and build both bundles. Use this before publishing. |
| `npm run generate` | Update only RSS, sitemap, and fallback post links. |
| `npm run generate:check` | Check for stale generated files without writing them. |
| `npm test` | Run the generator tests. |
| `npm run build:main` | Bundle only the homepage JavaScript. |
| `npm run build:blog` | Bundle only the blog JavaScript. |

Running `npm run build` inside the blog directory generates metadata and builds
only the blog bundle. It delegates to the root tools.

In VS Code, **Ctrl+Shift+B** runs the default `npm: build - main` task, which now
builds the entire site. **Terminal > Run Task** also offers the blog-only task.

## Is Anything Automatic?

Saving a file does not run this production build. There is no repository workflow
configured to run these npm commands on push. Earlier bundle updates were made by
explicit build commands, including commands run by the coding assistant.

Metadata generation now happens automatically whenever you run the full build or
the blog-directory build. The low-level `build:main` and `build:blog` commands only
bundle JavaScript. A running webpack development watcher does not regenerate the
RSS, sitemap, or fallback links.

The generated files are committed alongside the source so the static site can
serve them without running Node.js on the hosting server. After deployment,
[robots.txt](robots.txt) advertises the sitemap at
`https://codemonkeyprojectiles.com/sitemap.xml`; submit that URL in Search Console
once, rather than submitting a new sitemap for each post.
